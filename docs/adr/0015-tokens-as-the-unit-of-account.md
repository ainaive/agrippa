# ADR-0015: Tokens Are the Unit of Account — Agrippa Tracks No Money

- Status: accepted · Date: 2026-07-28

## Context

Agrippa priced every unit of work in US dollars. The `models` registry carried `input_cost_per_mtok` / `output_cost_per_mtok`; the engine multiplied each executor `usage` event against those rates into `token_usage.cost_usd`; templates capped runs with `budgets.maxCostUsd` and per-phase dollar ceilings; projects set a monthly `cost_limit_usd`; and the SPA rendered `$12.34` across the dashboard tile, the Usage page, the run header, the per-step timeline, and the admin model form.

Every one of those dollar figures was an inference, and the inference was unsound. List rates drift per provider and per region with no notification. Aliyun Bailian tiers Qwen pricing by *input length*, so a single per-MTok rate is wrong for any prompt above the entry tier — the seed comments said as much, telling operators to "verify against the live Model Studio price list". Codex under ChatGPT-account auth (`CODEX_HOME`) has no per-token price at all; the subscription is the price. Nothing in the product ever reconciled a computed figure against a provider invoice, and nothing could have: the platform has no billing integration, and `00-overview` has always listed billing as a non-goal. So a template that said `maxCostUsd: 8` was enforcing a number with no defensible relationship to money actually owed, and a Usage page that said `$4.12` was stating something the platform could not stand behind.

Tokens have none of these problems. They arrive from the executor in the `usage` event, they are what the engine already persists per `(run, step, attempt)`, and every SQL aggregate in the product already summed them alongside cost. The dollars were a lossy derivation layered on top of the honest measure.

A second, quieter problem: the price columns were doing double duty. Beyond accounting, `resolveSlotModels` used `inputCostPerMtok` as its **ordering key** — "cheapest in tier" for role resolution, and lowest summed input cost as the cross-provider tie-break. Deleting money would silently take model selection with it.

## Decision

1. **Tokens are the only unit of account. The product carries no monetary concept at all** — no pricing, no cost accounting, no currency in any payload, column, or rendered string. This supersedes the older non-goal wording ("billing/invoicing integration — cost accounting and quotas only"): cost accounting is now a non-goal too.
2. **Run limits are token limits.** Template `spec.budgets` becomes `spec.limits`; `maxCostUsd` becomes `maxTokens`, per-phase caps likewise. `maxDurationMinutes` moves across unchanged — it was never money. Builtins were converted once at **200 000 tokens per USD** (a blended ≈$5/MTok, the seeded strong tier's *input* rate, chosen because agent traffic is input-dominated). That multiplier is a one-time calibration recorded here for provenance; **nothing in the codebase converts between the units**, and no future change should reintroduce one.
3. **`BudgetMeter` becomes `UsageMeter`**, `BudgetExceededError` becomes `UsageLimitExceededError`, and the normalized error code `budget_exceeded` becomes `usage_limit_exceeded`. "Budget" reads as money to users and to the next person in the code; a meter that counts tokens should not be named for money. The meter keeps one token counter for the run and one per phase, both fed by **input + output, cache reads and writes excluded** — the same measure every usage aggregate and the submit-time quota gate use, so the two can never disagree.
4. **Project quotas are token-only.** `project_quotas.cost_limit_usd` is dropped; `token_limit` + `hard_stop` carry the whole feature, and the quota error code `quota_exhausted` is unchanged.
5. **`models.rank` replaces price as the selection key.** An integer, lower wins, ties broken by `provider_model_id`, defaulting to 100 for admin-created rows. Preference is now something an operator states explicitly rather than a side effect of a price nobody maintains.
6. **The money columns are dropped**, not merely orphaned: `token_usage.cost_usd`, `project_quotas.cost_limit_usd`, both `models.*_cost_per_mtok`, and `runs.budget` (a denormalized copy of limits whose authoritative source was always the pinned `template_versions.compiled` row).
7. **Every visualization survives, re-based on tokens.** "Daily spend" becomes daily tokens, "Spend by model" becomes tokens by model, the dashboard spend tile becomes a tokens tile, and the Usage page's second stat tile becomes remaining monthly headroom. Removing money was not a reason to remove the analytics built on it.

## Alternatives considered

- **Hide money in the UI, keep it in the schema and engine.** The smallest diff, and the worst outcome: the API would keep emitting `costUsd`, the engine would keep computing an unsound number, and the next contributor would reasonably surface it again. The problem is the figure's existence, not its visibility.
- **Keep cost accounting and fix the prices.** Not fixable in principle for the providers we actually support — Bailian's length-tiered rates need the prompt length at pricing time, and a ChatGPT-account Codex run has no per-token price to be correct about. Accuracy here would demand per-provider billing integrations, which is a product Agrippa is not.
- **Keep the price columns purely as a hidden ordering key.** Preserves selection behavior with zero migration, but leaves money in the schema and the admin API, so "the platform tracks no money" would be false in the only place that matters.
- **Order models alphabetically instead of adding `rank`.** No new column, but it changes today's preference order and makes "prefer this model" a renaming exercise.
- **Delete run/phase limits entirely, leaving only `maxDurationMinutes` and the project quota.** Less code, but the clock is a poor guard against a fast runaway loop, and the token meter that would be deleted was already there and already correct.

## Consequences

- **No billing story whatsoever.** An operator who needs spend attribution reads it from their provider's console, correlating on model and month. Agrippa reports tokens.
- **`rank` is maintained by hand.** Adding a builtin model means choosing where it sits (builtins are spaced by 10); admin-created models default to 100 and tie-break by model id. Migration 0010 backfills rank from the existing prices, ordered by `(input, output, provider, provider_model_id)`, so an upgraded deployment resolves exactly what it resolved before — verified against a database seeded from `main`. This also removes two pre-existing nondeterminisms: `qwen3.6-flash`/`gpt-5.1-codex-mini` (both $0.25) and `claude-opus-4-8`/`gpt-5.6-sol` (both $5.00) previously resolved by unspecified row order, since `fetchGrantedModels` has no `ORDER BY`.
- **Summed ranks are not summed prices.** The cross-provider tie-break sums an ordinal, which is not strictly monotone in a sum of prices for multi-role slots. With money gone the requirement is "deterministic and preference-ordered", not "price-equivalent"; the seeded fleet resolves identically either way.
- **Dropping the columns is irreversible.** Historical `cost_usd` values are discarded by migration 0011. Token counts, quotas, and every row are preserved.
- **Template versions published before this change keep working.** `upgradeCompiledTemplate` casts stored v2 rows without re-validating, so a row carrying `spec.budgets` and no `spec.limits` would have left the engine dereferencing undefined on its next pickup. It now normalizes: the duration cap survives, and the cost caps drop, because deriving tokens from a dollar figure needs a price the registry no longer stores. Those runs fall back to the duration cap and the project quota — deliberately, rather than inventing a token ceiling nobody authored. This path is permanent, not transitional: builtins republish on boot, but admin-authored versions and every run pinned to one keep their original compiled jsonb forever.
- **A draft still written against `spec.budgets` fails to compile** rather than silently losing its cap — zod strips unknown keys, so silence was the default failure mode.
- **Pre-migration runs still render `budget_exceeded`.** The code is persisted in `runs.error`, `run_steps.error`, and `run_events`, but nothing reads or branches on it (the SPA prints the raw code), so no data migration was warranted. Historical rows display their historical code; new failures say `usage_limit_exceeded`. Likewise, old `runs.usage_totals` jsonb retains a `costUsd` key that nothing reads.
